# 落笔 · 求职前置

> **简历的攻击面分析器**：不帮你写漂亮话，只帮你把做过的事写成**经得起追问**的话。
>
> 这是个创业项目，比赛只是它的一条分发渠道。定位、验证顺序、怎么死，都写在
> `docs/创业路线图-v1.0.md`。

---

## 一分钟跑起来

**Windows**：双击 `启动落笔.bat`（自动开浏览器）
**其他系统 / 手动**：

```bash
cd 简核
python server.py                 # 本地 127.0.0.1:8848
JH_HOST=0.0.0.0 python server.py # 部署到服务器
```

> 零第三方依赖，只要 Python 3.9+。**没有 pip install 这一步**——这是故意的：
> 目标用户是自己的电脑和一台最小配置的云主机，依赖链是最先崩的一环。

启动后会打印三行地址：站点、运营后台（带一次性密钥）、引擎模式。

## 现在能做什么

### 引擎（都是真逻辑，不是演示文案）

| 功能 | 实现方式 | 说明 |
|---|---|---|
| **导入解析** | 规则切分（板块标题 + 时间区间 + bullet） | 粘贴原文或上传 `.docx`/`.txt`；切完给确认，可逐项改 |
| **HR 诊断** | 纯规则引擎，四维打分 | 首屏 6 秒 / 经历价值 / 语言专业度 / 排版结构。每条问题都指得出是哪句、错在哪 |
| **岗位定向** | JD 关键词 ∩ 档案 + 硬门槛 + 隐性信号 | 匹配度、缺口词；"与算法团队协作"识别为**协作对象**而非技能要求 |
| **关键词召回**（v1.3 修） | 词库 165 词，**长词优先去重** | JD 写「数据分析」「用户增长」以前一个都抽不出来，白丢两个缺口；现在能认出来。同时修掉「MySQL 里含 SQL」这类子串重复——同一个要求算两次会让分母虚高、缺口列表重复报 |
| **逐条改写** | 规则版（离线）/ 大模型版（配 Key 后） | 三版侧重 + **数字防新增校验**：出现原文没有的数字直接标红 |
| **证据核验** | 抽数字回溯 evidence 字段 | 无证据的数字在预览标黄，点一下就能改 |
| **追问预测** | 按"可攻击点"生成 8–12 题 | 每题带考察点、STAR 框架、常见坑与排序 |
| **导出** | 浏览器打印，保留文字层 | 验证过正好 1 页，ATS 可解析 |
| **投递台账** | SQLite | 状态流转 + 截止日顶置 |

### 岗位地图 · 实习避坑（v1.2 新增）

这两块解决的是同一个问题：**「编简历编不圆满」**。
学生会写「负责私域运营」，但答不出「企微还是个人微信、多少个群、日活多少」。
差别不在词汇量，在于有没有**具体到不用回忆的事实**。

| 功能 | 做了什么 | 零成本可用 |
|---|---|---|
| **岗位地图** | 8 个岗位族 / 96 个词条：一句话定位、汇报对象、考核指标、日周月季节奏、行业上下游、组织内上下游 | ✅ 规则版 |
| **专业词汇** | 每词 5 个字段：释义 / 为什么这么叫 / 面试怎么说是加分 / **用错会被怎么问** / 难度等级 | ✅ |
| **诚实边界** | 三个阶段分别「能这么写 / 别这么写」，直接掐掉「独立负责」「从 0 到 1」这类越界表述 | ✅ |
| **细节题** | 每族 4 题，标准是「真做过能秒答、编的人必卡」。如「你负责的店是自营还是 POP？后台是平台后台还是生意参谋？」 | ✅ |
| **乱编检测** | 贴一段简历文字，按 6 条规则标出高风险表述（角色矛盾 / 量级越界 / 无口径的百分比 / 超 300% 提升 / 短期搭体系），每条给「会被怎么问 + 怎么改」 | ✅ |
| **实习坑库** | 42 条：12 条通用 + 30 条按岗位族。每条含 **场景 / 早期信号 / 事前怎么避 / 已踩怎么救 / 简历怎么写** | ✅ |
| **入职必问 8 句** | 把「有没有转正名额」「指导人是谁」这些该问但不敢问的话列出来 | ✅ |
| **AI 定制** | 接 DeepSeek 后，岗位地图和坑库都针对你的具体 JD 重新生成；调用失败自动降级到内置库，**不扣点** | ⚡ 扣点 |

> 关键设计：这两块**默认走规则引擎，成本为 0，永久免费**。
> AI 只是增量（针对具体 JD 定制），不是必需品。所以断网、没预算、演示翻车，功能都不会消失。

### 一岗一版 · 手机可用（v1.3 新增）

这两件事解决的是同一个问题：**用户在哪一刻放弃**。
不是"不会写简历"，是「投到第 5 家时，改来改去把通用版搞乱了」和「在微信里点开，电脑版根本没法用」。

| 功能 | 做了什么 | 为什么这样做 |
|---|---|---|
| **版本条** | 顶部一行 chips：每版显示名字 + 诊断/匹配分 + 投过几次，一次点击切换 | 求职者一天切十几次版本，任何"先保存再加载"的二段式操作都会被放弃 |
| **新建版本** | 以当前档案为底复制一份，绑到一段 JD 上；名字按「公司 · 岗位」自动生成 | 复制而不是"改一份"——用户不敢在唯一那份上试错 |
| **自动回写** | 改动只写当前版本（`/api/save` 顺手同步），切走再切回不丢 | 丢改动是最伤信任的一类 bug |
| **版本差异** | 和「没绑 JD 的那版」（通用底版）逐条对比：改了哪句、加了哪句、删了哪句、还差几个关键词 | 让用户确认"这一版真的为这个岗改过"，而不是自我感觉改过 |
| **按 JD 定制** | 逐条给出：原文 / 改后 / 覆盖了哪个 JD 缺词 / 为什么这么改 / **采用前必须确认什么**，一键采用 | 这才是付费点：不是"能不能用"，而是"给不给你能直接采用的句子" |
| **别写清单** | JD 要求但简历里完全没有的东西，明确说「别写」，并把缺词合成一句 | 宁可少一个关键词，也不要让用户面试崩在第一轮 |
| **手机版** | ≤860px：三栏变「对话 / 简历 / 诊断」分段；A4 缩略图换成 **阅读模式**（真 14px 响应式排版）；台账表格转卡片；弹窗全宽 | A4 在 390px 宽上缩放后正文只有 6px。手机端不是缩小版桌面，是另一种阅读方式 |
| **打印不动** | 手机上直接点导出，打印样式强制回 A4（`@media print` 单独覆盖阅读模式） | 手机上改，电脑上打，是真实工作流 |

> **计费边界**：版本管理、差异对比、规则版定制**全部免费**（不烧算力）。
> 只有 AI 版定制扣点；模型不可用时自动降级规则版并**不扣点**，且不会弹登录墙——
> 免费能力不能因为没登录就整块消失。

### 商业机制（v1.1 新增，这些才是创业项目的地基）

| 模块 | 做了什么 | 为什么 |
|---|---|---|
| **账号** | 邮箱 + PBKDF2 口令，Cookie 会话 | 不做短信（成本+备案）、不做三方登录（审核周期）。冷启动要验证的是付费意愿，不是登录体验 |
| **匿名可用** | 未注册能用全部功能，只在**导出**时拦 | 一上来给登录墙，转化率砍七成 |
| **数据迁移** | 注册时把 `s:xxx` 全批挂到 `u:xxx` | 不给用户"重来一遍"的机会 |
| **额度（credits）** | 注册送 3 次，导出扣 1 次 | 全产品唯一收费点，位置在产品价值最高处 |
| **兑换码** | 后台生成，用户自助激活 | MVP 收钱 = 微信收款 → 手工发码。零支付接口、零手续费、零合规风险 |
| **留资** | 撞墙时留微信/手机 | 说过要买但没买的人，比付费用户更值钱的前置信号 |
| **漏斗看板** | `/admin?key=xxx` | 七步漏斗 + 留存 + 解析失败率 + 自动诊断"最大漏点" |
| **未付费水印** | A4 预览平铺淡纹 | 挡截图，不挡阅读 |
| **会员 / 点数**（v1.2） | 会员 ¥4.9 一次性：不限次导出 + 知识库全解锁 + 赠 20 点；点数按 AI 调用扣，1 点 ≈ 一次完整分析 | 导出不烧算力所以敢放开；AI 有真实成本所以按点走。**详见 `docs/定价与成本模型-v1.0.md`** |
| **成本计量** | 每次 AI 调用记 prompt/completion token、真实成本、实收，后台算毛利 | 按量计费的产品如果不知道自己花了多少钱，就是在赌 |

## 运营后台

```bash
JH_ADMIN_KEY=你的密钥 python server.py
# 打开 http://127.0.0.1:8848/admin?key=你的密钥
```

不设 `JH_ADMIN_KEY` 会随机生成并打印在启动日志里。后台能看：

- 头部 KPI：注册、24h 活跃、导出、兑换码使用率、留资
- 七步漏斗（**统一按人数**——混用次数会算出 300% 这种自欺欺人的转化率）
- **自动结论**：掉得最狠的那一步 + 该做什么，不用自己对着数字猜
- **钱与成本**：实收现金 / 算力成本 / 毛利 / 会员数 / **未消耗点数（这是负债，不是利润）**
- 生成兑换码（会员码或点数包）、看用户、看留资

## 部署

完整手册见 `docs/部署上线手册.md`（Docker / systemd / Caddy 自动 HTTPS / 内网穿透救急 / 备份 / 监控）。

**当前线上试玩地址**：<https://jianhe-resume.app.workbuddy.host/?sharecode=K2YU5KXDPI>
（托管在发布沙箱，规则引擎模式，**不配置 API Key**。定位是演示与试玩入口，不是生产环境——
沙箱容器重建后 SQLite 可能不保留，所以不要在线上卖会员、也不要往里存真实简历。）

以下是自备服务器的跑法。**三种跑法，端口约定各不相同**（`server.py` 已按这个顺序自动判断，不用改代码）：

| 跑法 | 启动方式 | 监听 |
|---|---|---|
| 本地双击 | `启动落笔.bat` → `python server.py 8848` | **只绑 127.0.0.1**，简历不进局域网 |
| 自备服务器 / Docker | `JH_HOST=0.0.0.0 JH_PORT=8848` | 绑 0.0.0.0 |
| 托管平台（含 WorkBuddy 发布应用） | 平台注入 `PORT` | 自动绑 0.0.0.0 |

> 第三条是最容易踩的：平台只注入 `PORT`，如果你的服务只认自己的端口号、还绑在 127.0.0.1 上，
> 反向代理连不进来，会报成「启动失败」而不是「端口写错了」——排查方向会被带偏。
>
> 另一条只在托管环境才踩得到的坑：网关要求**每个请求都带分享码**，包括 `app.js`、`styles.css`
> 和所有 `/api/*`。它靠首次带 `?sharecode=` 访问时下发的 `__wb_rsc` Cookie 放行，所以浏览器正常打开
> 就没问题；用 `curl` 裸调接口会被拦成 403「链接不完整」，那不是服务挂了。

```bash
docker build -t jianhe:1.3 .
docker run -d --name jianhe --restart=always \
  -p 127.0.0.1:8848:8848 -v /opt/jianhe/data:/app/data \
  -e JH_ADMIN_KEY='换成长随机串' jianhe:1.3
```

**架构上唯一要坚持的一条**：`core/` 不认识 HTTP。哪天要换 FastAPI + Postgres，
`core/` 原样搬走，只重写 `server.py` 和 `store.py`。这是为了不把自己锁死。

## 现在明确没做

- **手机端**只做了适配，没做手势（左右滑切面板）与离线缓存。微信内置浏览器的打印入口很隐蔽，
  手机上导出的正确姿势仍是"手机改 → 电脑打"，产品文案里也这么写。
- **服务端 PDF 导出**：走浏览器打印，Playwright 版排在后面。
- **支付接口**：手工发码。**这是故意的**——先确认有人愿意付，再接支付。
- **复杂排版解析**：表格型/双栏 PDF 会切错，纯技术债。
- **自由对话**：当前是意图路由，不是自然语言对话。
- **岗位族只覆盖 8 个**：财务/审计、法务、设计、教师、供应链还没写。
  加一个族 = 在 `core/industry.py` 里加一个 dict，结构已定，不用改代码。
- **坑库是公开经验归纳**，不是调研数据。没有样本量，也不该有——编造比例数字比不给更糟。

诚实的优先级在 `docs/创业路线图-v1.0.md` 第八节。
