## 0. 一页纸

**产品**：OfferFit（工作名；备选 OfferFit）—— 大学生的求OfferFit习工具。

**一句话**：把简历改到位、把面试练到位，练完知道下一步补什么。

**不是**：招聘平台、模板站、AI 代写、3D 写实数字人、面试防作弊。

**核心闭环**：

```
① 导入简历 ─▶ ② 贴 JD 优化 ─▶ ③ 数字人模拟面试 ─▶ ④ 逐题评分复盘 ─▶ ⑤ 低分改写/错题 ─▶ ⑥ 学习建议 ─┐
      ▲                                                                                                    │
      └────────────────────────────────────────── 再练 ◀──────────────────────────────────────────────────┘
```

**差异化的三件事**（按重要性）：
1. **真实、可追问**：不帮你编，只帮你把做过的事写成经得起追问的话（继承上版）；
2. **练习闭环**：评分 → 低分改写 → 重录重练，不是"聊完就结束"；
3. **低压力开口**：简笔画数字人降低"被评判感"，让不敢开口的人先敢说。

**第一版（MVP）只做工具闭环**：简历优化 + 文字/语音面试陪练 + 复盘报告。社区、竞赛、机会库都不做。

## 1. 用户与场景

### 1.1 目标用户（首期收窄）

| 优先级 | 用户 | 特征 | 核心诉求 |
|---|---|---|---|
| P0 | 大三找实习 | 第一份简历，经历少、不敢开口 | 把课程项目/社团经历写出价值；先练到敢投 |
| P0 | 大四秋招/补录 | 投了很多没回音、面试紧张 | 一岗一版；针对目标岗练高频问题 |
| P1 | 转行/跨专业 | 有经历但不会翻译成岗位语言 | 岗位地图 + 术语 + 诚实边界 |

首期场景收窄到**互联网/软件类校招**，非技术岗先复用同一套引擎。

### 1.2 核心场景（JTBD）

1. **投递前**：拿到一个 JD，想知道"它到底要什么、我缺什么、简历往哪改"；
2. **面试前**：想有人按我的简历和 JD 提问，还会追问，而不是背题库；
3. **面试后**：想知道刚才哪句答得差、差在哪、该怎么重说；
4. **连续求职**：投了哪些、到哪一步、哪次面试暴露了什么弱项，别断掉。

## 2. 核心闭环（六步，每步都有明确产出）

| 步 | 用户动作 | 产品产出 | 依赖的上版资产 |
|---|---|---|---|
| ① 导入 | 粘贴/上传旧简历，或从零填 | 结构化档案 + 完整度 | `parse` `profile` |
| ② 优化 | 贴 JD | 匹配分 + 缺口词 + 逐条改写（带事实校验）+ 改前改后对比 + 一页 PDF | `lint` `jd` `rewrite` `variants` |
| ③ 练习 | 选岗位/JD，开一场 | 数字人语音/文字提问 + 多轮追问（引用你的回答） | 新增（Agent + 语音 + 数字人） |
| ④ 复盘 | 看报告 | 逐题评分（可解释）+ 录音回放 + 转写 | 新增（评分体系） |
| ⑤ 改写 | 点低分题 | 参考答案 + 为什么这么改 + 重录重练 | `rewrite` + 自定义评分 |
| ⑥ 学习 | 看弱项 | 岗位技能差距 → 学习路径 | `industry` + 新增学习库 |

> 闭环的"钩子"：每场练习结束不是终点，而是下一次练习的起点（错题本 + 训练计划）。

## 3. 功能范围

### 3.1 P0（MVP，必须有）

| 模块 | 需求 | 验收要点 |
|---|---|---|
| 简历导入 | 粘贴文本 / 上传 docx / 手动填 | 解析后可逐项修正 |
| 简历优化 | JD 关键词、匹配分、缺口、逐条改写、数字防新增 | 每条建议可执行，能指出是哪句 |
| 简历导出 | 1 页 A4 PDF，保留文字层 | ATS 可解析；手机改、电脑打 |
| 面试出题 | 基于简历 + JD，多轮追问，引用回答 | 至少 5 轮；追问不是题库 |
| 对话形式 | 文字（必做）+ 语音（录音/转写/TTS） | STT/TTS 失败自动切文字，不丢记录 |
| 数字人 | 五状态 + 嘴型随音量 | 轻量、首屏不卡；低端设备降级静态图+字幕 |
| 逐题评分 | 内容/结构/具体性/表达 四维，可解释 | 每条评分指到原话；标注"练习参考" |
| 复盘报告 | 逐题 + 录音回放 + 弱项汇总 | 可保存、回看、删除 |
| 账号与数据 | 邮箱账号、匿名可用、导出/删除 | 录音与简历加密存储 |
| 投递台账 | 公司/岗位/阶段/截止 | 与练习记录关联 |

### 3.2 P1

- 低分回答改写 + 重录重练 + 错题本 + 训练计划；
- 面试官人格（同级/资深/压力型）；
- 学习建议（技能差距 → 路径）；
- 数字人可动资产升级（眨眼/转头/呼吸）；
- 多模型 Provider 切换 + 本地 Ollama/Whisper 隐私模式。

### 3.3 P2

- Live2D / 更强表现力；管理后台（模板/题库）；
- 多代理求职流水线（先不做）。

## 4. 信息架构（工具优先）

```
OfferFit（Web 优先，手机可用）
├── 工作台（首页）        今天该做什么：待优化简历 / 待练岗位 / 最近弱项
├── 简历
│   ├── 档案与诊断       完整度、四维评分、逐条问题
│   ├── JD 优化          匹配分、缺口、逐条改写、改前改后
│   └── 版本与导出       一岗一版、差异对比、PDF
├── 面试陪练
│   ├── 开场             选岗位/JD/人格/时长
│   ├── 练习中           数字人 + 提问 + 追问 + 文字/语音切换
│   └── 复盘报告         逐题评分、回放、参考答案
├── 错题与训练           错题本、重练、训练计划
├── 投递台账             公司/岗位/阶段/提醒
├── 设置                 账号、隐私、数据导出删除、模型 Key
└── 运营后台（admin）     漏斗、成本、题库、模板
```

**设计原则**（继承上版验证过的）：
- 免费能力不设登录墙，只在"导出/语音场次"处收费；
- 核心链路规则引擎可离线，语音/数字人失败可降级；
- 手机端是另一套信息架构（分段 + 语音优先），不是缩小版桌面；
- 打印契约不能破坏：1 页 A4 + 文字层。

|---|---|---|---|
| D1 | 简历渲染 | ✅ **自建浏览器打印（1 页 A4）**，不整体自托管 Reactive Resume | RR 是完整产品（Postgres + 存储 + 账号 + 日更升级 + 字体镜像），接入 5–8 人日；其 A4 数值 / 中文标题词表 / CJK 字体策略可零成本借鉴 → [`refs/notes/p0-reactive-resume.md`](<../refs/notes/p0-reactive-resume.md>) |
| D2 | 面试 Agent | ✅ **自研**（上版 `drill`/`interview` 规则 + LLM），5–8 人日（+语音 3–5）；不改造 offerMaster | offerMaster **仓库无 LICENSE**（README 口头 MIT ≠ 授权），代码/提示词不能复制；其「LangGraph」名不副实（代码 0 import，纯函数 + FastAPI 状态机）→ [`refs/notes/p0-offermaster.md`](<../refs/notes/p0-offermaster.md>) |

### 7.2 三线调研总览（已完成）

| 线 | 主要结论 | 笔记 |
|---|---|---|
| **P0 四库** | Reactive Resume 是完整产品不是渲染库（自建更省钱）；Resume Matcher 的确定性 ATS 打分 + CJK 关键词匹配最值钱；offerMaster 无 LICENSE 且「LangGraph」名不副实；player 可作为口型算法参考 | `refs/notes/p0-*.md`（4 份） |
| **数字人 / 语音** | D3 半双工 + 句级流式 TTS（5–8 人日）；D4 自研 canvas2D PNGTuber（2.5–3.5 人日）；资产：手绘 5 base + 3 嘴 + 2 眼，约 300KB，插画师 1–2 天/角色 | `refs/notes/avatar-*.md`（4 份） |
| **简历 / ATS / 学习** | ATS 做成**并列第二张清单**、不给总分（防刷分/防造假）；引入第四态 `skipped`（没检查 ≠ 通过）；模板只做 3 套 + 学生/社招开关；学习路径走「岗位要求 → 我有什么 → 加权差距 → 资源 → 顺序」 | `refs/notes/resume-*.md`（4 份） |

**顺带发现的两个"必须现在做"**（越晚越贵）：
1. **数据 user/system 分层**（0.5 人日）：上版 `data/jianhe.db` 在仓库里，打包/更新会丢用户数据；
2. **规则文件化**：上版规则散在 `lexicon/lint/industry/pitfalls/prompts` 五处，再加 ATS 与学习路径必然两处定义不一致。

**成本粗估**：P0 简历线约 42 人日（ATS 6 / 模板 9.5 / 学习路径 17.5 / 流水线 9）；数字人+语音约 8–11 人日；加上通用后端与前端，MVP 合计约 **60–75 人日**（不含美术资源）。

### 7.3 D5「技术栈」是什么（一句话解释）

就是**用什么语言/框架写这个产品**，有三个影响：能不能接语音流、后端要不要重写、部署麻不麻烦。

| 方案 | 好处 | 代价 |
|---|---|---|
| **FastAPI + 原生 JS（推荐）** | Python 生态接 STT/TTS/LLM 最顺；上版 `core/` 引擎可直接搬；前端零构建 | 需要装 Python 依赖（不再是上版「零依赖」） |
| Next.js 全栈 | 前后端一体、部署一个服务 | 上版 Python 引擎要重写或做胶水 |
| Python 标准库（上版风格） | 零依赖、可打 exe | 语音/流式/并发会很吃力 |

> 这个决策**不影响可点原型**（原型是纯 HTML），可以等原型确认后再定。

## 9. MVP 验收标准（沿用概念 §8，补量化）

- [ ] 用户能完成"上传简历 → 贴 JD → 得到优化建议 → 导出 PDF"，PDF 排版正确；
- [ ] 用户能完成 **至少 5 轮** 文字或语音面试，追问引用其回答内容；
- [ ] 每场面试生成逐题评分（四维、可解释）+ 可回放录音/转写；
- [ ] 数字人：TTS 播放时嘴型变化；用户说话进入倾听；反馈时表情变化；
- [ ] 练习记录可保存/回看/删除；简历数据可导出/删除；
- [ ] 给出语音延迟与单场成本的实测结论（或校准后的目标）。

## 11. 边界（明确不做）

- 不做完整招聘/投递平台（Offer Desk 不并入）；
- 不做真人面试官匹配；
- 不做 3D 写实数字人与视频防作弊；
- 不做"保 offer"承诺；
- 不做 AI 代写整份简历（只做"改写 + 必须确认"）。

## 12. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 数字人效果差（嘴型不自然） | 观感崩、留存掉 | MVP 卡通化 + 少帧 + 状态表情；不追求写实 |
| 语音延迟/打断体验差 | 用户放弃 | 半双工兜底 + 文字模式 |
