## 0. 一句话结论

**上一版和新概念不是两个产品。**

- 上一版（落笔）= 把简历改到「敢投」+ 知道会被怎么追问；
- 新概念（OfferFit）= 把这个闭环补上「**练**」：数字人陪练 → 逐题评分 → 低分改写 → 重练 → 学习建议。

合并后的产品应该是一句话的两个半句：**「把简历改到位、把面试练到位，练完知道下一步补什么」**——这句是新概念 §1.3 的原话，也是最准确的定位，建议直接采用。

## 4. 新概念带来的三个新工程块

### 4.1 数字人表现层

- MVP：手绘闭嘴 / 半张 / 张嘴 / 眨眼几帧，播放器按 TTS 音量包络切帧，5 状态机（待机/倾听/思考/说话/反馈）；
- 风险：简笔画自动分层效果差 → 概念里已用「PNGTuber 多帧」绕开，判断正确；
- 决策点：播放器自研（约 200–400 行，零依赖）还是接 `livliv-dev/player` → 见 §5 D4。

### 4.2 语音管线

- MVP 建议：**浏览器录音 → 上传 → STT → LLM → TTS → 播放**（半双工），不做实时打断；
- P1：WebRTC / 实时 barge-in（参考 `voice-agent-kit` / `fastRTC-voice-agent`）；
- 降级：STT/TTS 失败自动切文字模式（沿用上版「模型失败降级不扣点」的思路）。

### 4.3 评分与复盘体系

- 维度建议：内容相关性 / 结构（STAR）/ 具体性（数字与细节）/ 表达（长度、口头禅）/ 岗位匹配；
- 每条评分必须能指到「用户原话 + 缺什么 + 怎么改」，禁止只给分数；
- 标注「练习参考，非录用结论」（概念 §6 已要求）。

## 6. 与上版结论的冲突点（必须注意）

| 上版结论 | 新概念要求 | 冲突与处理 |
|---|---|---|
| 零第三方依赖、断网可用、可打 exe | 多服务 + LLM + STT + TTS + 数字人 | **部署复杂度上升是必然代价**；处理：核心简历链路保持「规则可离线」，语音/数字人作为增强层，失败可降级 |
| 收费点在「导出」 | 主价值在「练习」 | 收费点需重设（D7） |
| 手机端是另一套信息架构 | 新概念 Web 优先 + 移动浏览器兼容 | 保留上版做法，面试陪练在手机上做「语音优先」 |
| 规则引擎兜底、不扣点 | 语音/LLM 成本更高（<¥2/场） | 需要更严的额度与降级策略；上版 `billing` 成本计量直接复用 |
