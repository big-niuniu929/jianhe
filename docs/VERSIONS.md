| tag | 时间 | 形态 | 关键差别 |

| `v1.3-luobi` | 2026-10 | `落笔 · 求职前置`：`server.py` 单文件服务 + `core/` + `web/`，零第三方依赖 | 已跑通商业闭环：账号、额度、兑换码、留资、漏斗后台、成本计量；岗位地图、一岗一版、手机端都在这一版 |

## 为什么不直接在 v1.3 上改

`server.py` 65 KB 里有 HTTP 路由、渲染、模板和业务逻辑；想加一个 ATS 检查要动同一个文件。v0.2 的拆法是把「判定」全放进 `app/engine/`（纯函数、可单测），`main.py` 只做路由与编排。这样加一个引擎能力 = 加一个模块 + 一个路由，不用碰别的。

## 引擎演进

1. **v1.0**：规则版逐条改写 + 四维诊断。问题：关键词召回漏词（JD 写「数据分析」「用户增长」一个都抽不出）
2. **v1.3**：词库扩到 165 词并改长词优先去重（同时修掉「MySQL 里含 SQL」的子串重复，避免分母虚高）
3. **v0.2**：拆引擎 + 加 ATS 结构预检与渲染预检（只给计数不给分，总分留给四维诊断），面试从「生成问题」走到「练完给复盘」

贯穿的原则：**大模型只负责写，判断权留在规则里**。规则可解释、可累积、断网也在。
